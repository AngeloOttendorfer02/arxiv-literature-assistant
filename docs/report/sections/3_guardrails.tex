\section{Guardrail Verification and Security Harness}
\label{sec:guardrails}

\paragraph{Adversarial input defense.}
Before any database or model call, \texttt{check\_input} runs three stages.
(1)~Prompt Guard~2 (86M, threshold 0.5) scores the query in windows of at most 512 tokens and takes the highest score; it misses requests for the assistant's own instructions (``print your system prompt'' scores 0.003), so about eight English and German patterns cover them.
(2)~The topic gate compares the query embedding with hand-written prototype sentences of three classes (literature question, off-topic, write request) and refuses when a disallowed class is closer.
(3)~Presidio masks e-mail addresses, phone numbers, card numbers, IBANs and IP addresses; names stay, as authors are search terms.
A refusal carries its category (injection, off-topic, write intent), which the UI shows; tests assert that no SQL and no model call ran.
The database role can only \texttt{SELECT}.
Against indirect injection, the evidence guard scores every retrieved chunk and abstract with Prompt Guard~2 and drops it at 0.5 or above; SQL tables are built by our code and not scored.

\paragraph{Output groundedness and citation mapping.}
The model sees numbered evidence and may only emit labels $[1],\dots,[n]$; per request the code maps each label to a chunk ID, a paper ID or the query ID of an SQL table.
Each streamed sentence is held back until it passes:
(i)~valid labels at its end;
(ii)~every number and year in it occurs in a cited source, SQL rows included;
(iii)~for non-SQL sources, the NLI model ModernCE-large-nli takes each cited source as premise and the sentence without labels as hypothesis; one source with entailment $\ge 0.5$ suffices, a contradiction $\ge 0.5$ counts as a factual mismatch.
Failed sentences are removed and counted; passed ones are rendered by code, which replaces each label by title, year, chunk and paper ID, passage and a SHA-256 fingerprint of the source.
\paragraph{Efficacy.}
All cases are our own (one author per set), split into tuning and test; Table~\ref{tab:guardrails} reports the test split at the thresholds in use.
The 23 injection test cases are 10 jailbreaks, 7 direct instruction overrides and 6 system-prompt exfiltrations; the 49 harmless cases are literature questions of all three scenarios, some in German.
A rule fixed beforehand (highest DSR with at most 5\,\% FRR on tuning) did not separate the Prompt Guard thresholds 0.5 and 0.7 on tuning, so the default 0.5 stayed.
The query guards refuse 94\,\% of 50 attacks and 2\,\% of 49 harmless questions; only 57\,\% of the injections get the injection category, since the topic gate catches some jailbreaks as off-topic.
The evidence guard removes a third of 12 injected passages and none of 3 with the instruction in the middle; 0.01 would catch half but would also remove 7\,\% of 200 real chunks, so 0.5 stays.
The sentence check removes 97\,\% of 38 manipulated sentences (changed numbers, negations, added claims, wrong source) but also 26\,\% of 23 faithful ones, among them all 4 that combine facts of two passages, because each source is judged alone.

\paragraph{Overhead.}
With the evidence guard and NLI on the GPU the guards cost 1.5\,s per request (p95 1.8\,s).
The sentence checks dominate (1.0 of 1.5\,s, about 0.21\,s per sentence, mostly the round trip to Modal); since a sentence is released only after its check, they delay the first visible sentence by 0.22\,s.
In live runs, the check removed our own code's notice that only an abstract is available, which no abstract can entail; it now passes by exact template match and is sent once per answer, and on the 12 questions of Section~\ref{sec:benchmarks} the share of removed sentences fell from 52\,\% to 24\,\%.
